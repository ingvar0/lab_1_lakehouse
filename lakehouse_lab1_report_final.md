## 1. Цель

Развернуть локальный Lakehouse, подготовить Bronze/Silver/Gold, выполнить TPC-H Q3, проверить работу Iceberg и сравнить Parquet GZIP и ZSTD. Дополнительно подключить BI-инструмент к данным Bronze.

## 2. Архитектура

- **Docker Compose** — управление локальными сервисами.
- **SeaweedFS** — S3-совместимое объектное хранилище (вместо MinIO, образ которого не удалось использовать в этой среде).
- **PostgreSQL 17** — хранение служебных метаданных каталога.
- **Lakekeeper** — Iceberg REST Catalog.
- **Trino 476** — SQL-движок, доступ к TPC-H SF1 и Iceberg.
- **Apache Iceberg + Parquet** — табличный формат и файлы данных.
- **Metabase** — BI-просмотр Bronze через драйвер Starburst/Trino.

Поток данных: `tpch.sf1` → `iceberg.bronze` → `iceberg.silver.shipping_orders` → `iceberg.gold.top_orders`. Дублирующий Bronze с ZSTD расположен в `iceberg.bronze_zstd`.

## 3. TPC-H Q3 и преобразования

Параметры запроса: сегмент покупателей `BUILDING`, дата `1995-03-15`. Объединяются `customer`, `orders`, `lineitem`; доход вычисляется как `SUM(extendedprice * (1 - discount))`, группировка по заказу, дате и приоритету; сортировка по убыванию дохода, топ-10.

Silver — подготовленные строки для Q3 после соединений и фильтров. Gold — 10 заказов с наибольшим доходом.

### Размер файлов Parquet

**Актуальные измерения на текущих таблицах:**

| Таблица | GZIP, МиБ | ZSTD, МиБ |
|---|---:|---:|
| customer | 7,70 | 7,80 |
| orders | 33,50 | 34,90 |
| lineitem | 144,00 | 147,70 |
| **Итого** | **185,20** | **190,40** |

ZSTD занимает на 5,20 МиБ (около 2,81% относительно GZIP) больше места на трёх таблицах. Разница для `lineitem` составляет 3,70 МиБ.

Измерение — сумма `file_size_in_bytes` в метаданных Iceberg `$files`; это размер файлов данных, без учёта метаданных и накладных расходов объектного хранилища.

## 6. Возможности Apache Iceberg

**Schema Evolution:** создана `iceberg.silver.shipping_orders_demo` на 10 строк; выполнено `ALTER TABLE ... ADD COLUMN processing_status VARCHAR`. `DESCRIBE` подтвердил появление поля.

**Time Travel:** исходный snapshot ID `4471103206993218091`; после `INSERT` текущая таблица содержала 11 строк, а чтение `FOR VERSION AS OF 4471103206993218091` вернуло 10 строк.

**Rollback:** выполнено `ALTER TABLE iceberg.silver.shipping_orders_demo EXECUTE rollback_to_snapshot(4471103206993218091)`; повторный подсчёт вернул 10 строк. Исходная Silver-таблица не менялась.

## 8. Ограничения и устранение проблем

Эксперимент проводился на MacBook Air с 8 ГБ оперативной памяти; Docker Desktop выделено 4 ГБ. При первоначальной массовой загрузке Trino завершился с `OOMKilled=true` и кодом 137. Для стабильности установлены лимит памяти контейнера Trino `2500m`, JVM heap `-Xmx1536M`, снижена `task_concurrency` до 1–2; `lineitem` загружалась непересекающимися диапазонами `orderkey`, между тяжёлыми операциями перезапускался только Trino. После повторного развёртывания все таблицы и результаты были успешно восстановлены.

Во время загрузки ZSTD встречалась ошибка `No nodes available to run query` вскоре после перезапуска Trino; продолжение стало возможным после готовности SQL-движка. Ошибка `bootstrap exit 22` при добавлении Metabase обойдена запуском `docker compose up -d --no-deps metabase`, без повторной инициализации каталога.

## 9. Вывод

Локальный Lakehouse с объектным хранилищем SeaweedFS, каталогом Lakekeeper и движком Trino успешно реализован. Построены слои Bronze, Silver и Gold, результат Q3 сверен с источником; протестированы GZIP и ZSTD, Schema Evolution, Time Travel, rollback и подключение Metabase.
